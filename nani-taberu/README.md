# なに食べる？アキネーター

食べたい料理が思いつかない時に、数問の質問に答えるだけで料理候補を絞り込む PWA。
今日のやる気（作りたくない〜凝りたい）で無理なく作れる料理に絞り、
「こってりした肉系」「トマト系」「カレー以外で」「炒めるだけで」のようにざっくり入力して始めることもできる。

仕様は [SPEC.md](SPEC.md)、料理データの一覧は [docs/dishes.md](docs/dishes.md)。

## 開発

```bash
npm install
npm run dev       # 開発サーバー
npm test          # ロジックのユニットテスト（vitest）
npm run build     # 型チェック + 本番ビルド（dist/、Service Worker 付き）
npm run preview   # ビルド結果を確認（オフライン動作もここで確認できる）
npm run build:single  # 試用ページ用の単一 HTML（dist-single/、Service Worker なし）
npm run data:table    # dishes.json から docs/dishes.md の一覧を作り直す
```

`base: './'` にしてあるので、`dist/` をそのまま GitHub Pages などのサブパスに置ける。

## 構成

```
src/
  data/dishes.json      料理データ（63品。属性タグ・食材・やる気度）
  data/ingredients.json 食材辞書（正規名 → 別名・カテゴリ）
  data/categories.json  カテゴリ語（「きのこ」「豆腐系」など）
  data/keywords.json    フリー入力の辞書（言葉 → 属性タグ・やる気・包丁）
  logic/types.ts        型定義
  logic/questions.ts    質問の定義（主材料は「主食」「メイン食材」の2問に分割）
  logic/engine.ts       絞り込み・スコア計算・次の質問の選択・終了判定（純粋関数）
  logic/freeText.ts     フリー入力の解析（食材・料理名・属性語の最長一致、否定表現）
  logic/text.ts         入力の正規化（ひらがな／カタカナ、全角／半角）
  logic/display.ts      結果画面のやる気バッジと理由の1行
  logic/interpreter.ts  フリー入力解釈のインターフェース（将来 LLM 実装を差し込む場所）
  screens/              スタート / フリー入力 / 質問 / 結果 画面
```

## ロジック

- 絞り込み（ハードフィルタ）：「違う！」で除外した料理 → 食材・料理名の否定 → 包丁なし → やる気度。
  やる気度で3品未満になるときはレベルを1つずつ上げる（食材の指定が範囲外ばかりのときも同じ）。
- 食材・料理名の指定は main +3、sub +1、料理名 +3。3品以上当たれば当たった料理だけに絞り、
  1〜2品なら必ず残して近い料理も加える。複数指定は両方に当たる料理を上位にする。
- 回答ごとに、一致した料理は +1、不一致は −1、スキップは変化なし。
- 残り候補 = 最高スコアと同点の料理。
- 次の質問は、残り候補を選択肢ごとに分けたときのエントロピーが最大の質問。
  選択肢は残り候補に存在する値だけを出す（2〜5個）。
- 最初に「今日のやる気は？」を聞く（やる気度を含めて全8問）。最大 8 問、候補が 3 品以下、または聞いても絞り込めなくなったら結果へ。
- 「違う！」で今の第1候補を除外し、次点を表示。
- フリー入力は辞書の言葉を左から最長一致で拾い、直後に「じゃない／以外／は嫌／ない」等が
  続けば否定（その値を持つ料理が −1、持たない料理が +1）。肯定で判明した属性の質問は
  質問済みになり、残りの属性だけ質問する。何も拾えなければアキネーターモードへ誘導する。
  入力文は保存しない。
