## 目的
食べたい料理が思いつかない時に、数問の質問に答えるだけで料理候補を絞り込むアプリ。
「今日どのくらい作る気があるか」（やる気度）を軸に、無理なく作れる料理を選べるのが特徴。
「トマト系が食べたい」のように、食材や料理名から入ることもできる。
事前に登録した自分のプロフィールと、今の時間・状況・近所のスーパーの営業時間を踏まえて、「今からならこう動く」という段取りまで提案する。
さらに、提案した料理と実際に食べた料理を内部カレンダーに記録し、食事のバランスを考えた提案ができるようにする。

## 技術
- PWA（スマホ・Chromebook両対応、ホーム画面に追加可能）／Vite + React + TypeScript
- バックエンドなし。データは静的JSON＋localStorage
- 第1段階は外部APIなし（将来AI連携・地図連携を足せる構造にしておく）

## 食材・料理名の指定（A）
- dishes.json の各料理に ingredients（{ name, role: main|sub }）。食材名は ingredients.json の正規名にそろえる。main 1〜3、sub 0〜5、調味料は入れない
- ingredients.json：正規名 → { aliases, category }。照合前に入力を正規化（ひらがな／カタカナ、全角／半角、英字小文字、前後空白）
- カテゴリ語（「きのこ」「豆腐系」など）はそのカテゴリの食材を持つ料理すべてが対象
- 料理名は部分一致（「カレー」→名前にカレーを含む料理）。aliases も照合
- スコア：main +3、sub +1、料理名 +3、当たらない料理は加点なし
- 3品以上当たったら当たった料理だけに絞る。1〜2品なら必ず残して近い料理も加え「『トマト』を使う料理は2品でした。近い料理も入れています」
- 複数指定は AND（両方使う）を上位、足りなければ OR
- 否定（以外／は嫌／抜き／なしで）はその食材を使う料理を除外（sub 含む）
- やる気度と同時に効く。食材で絞った結果がやる気度の範囲外ばかりなら、やる気度を先に緩和して表示
- 辞書にあるが料理データにない食材：「『◯◯』を使う料理はデータにありませんでした」＋同カテゴリの料理で代替、console に警告
- どれにも当たらない：「うまく読み取れませんでした」→アキネーターモードへ
- 読み取った言葉を決定直後に確認表示し、タグをタップで外せる。結果画面に理由を1行

## やる気度（B）
| レベル | 表示名 | 意味 |
|---|---|---|
| 0 | 作りたくない | 買う・外食・お惣菜で済ませたい |
| 1 | 温めるだけ・茹でるだけ | 包丁なし。レンジ・お湯・混ぜる程度。1工程 |
| 2 | 炒める・焼くだけ | 包丁はほぼなし。フライパン1つ |
| 3 | ふつうに作れる | 包丁OK。数工程あってもよい |
| 4 | 凝りたい | 煮込み・仕込みなど |

- 料理に effort（1〜4）、knife（不要/少し/必要）、method（温める/茹でる/炒める/焼く/煮る/揚げる/和える/混ぜる）、deliAlt
- effort 1 は knife 不要のみ、effort 2 は不要か少し
- 選んだレベル以下の料理だけ（ハードフィルタ）。0 は style に外食を含むか deliAlt の料理だけ＋「作らない前提で…」表示
- 包丁なし指定は knife 不要のみ
- 3品未満ならレベルを1つ上げて再計算し「やる気の範囲では候補が少なかったので、少しだけ手間が増える料理も入れています」
- アキネーターモードの最初の質問「今日のやる気は？」（スキップ可）。進捗はやる気度込みで Q1/8
- フリー入力：作りたくない→0、温めるだけ→上限1、茹でるだけ→上限1＋茹でる、炒めるだけ／焼くだけ→上限2、めんどくさい→上限2、凝りたい→4、包丁なし→knife 不要。複数あれば低い方。拾えたらやる気度の質問は質問済み
- 結果にやる気バッジ（［炒めるだけ］［包丁なし］）と理由

## 外部検索への連携（C）
- 外部APIなし。検索語を端末内で組み立て、新しいタブ（target=_blank, rel=noopener noreferrer）で開く
- 該当なし食材：［検索で探す］／読み取れない入力：［この言葉で検索する］（入力文そのまま）／候補切れ：［検索で探す］
- 結果の第1〜3候補：［レシピを探す］［画像を見る］、下部に［近くのお店で探す］（レベル0では上に目立たせる）。質問画面では出さない
- 検索語：食材・料理名 ＞ やる気度（上限1→レンジ 簡単、2→炒めるだけ 簡単）・包丁不要 ＞ 味 ＞ 温度、条件語は最大5語。
  「レシピ」はレシピ検索だけ。否定した食材は Google（通常・画像）のときだけ「-トマト」
- 開く前に検索語を表示し編集できる。オフライン時はボタン無効。外部に渡るのは検索語だけ
- 設定：レシピ検索の開く先（Google検索／クックパッド／YouTube）。クックパッドは https://cookpad.com/jp/search/（検索語）

## やる気度の複数選択と楽／凝る切り替え（D）
- 「今日のやる気は？」は複数選択＋［これで決める］。1つ＝そのレベル以下、2つ以上＝最小〜最大（飛び飛びも連続扱い）、0＋他＝外食・お惣菜 ∪ 自炊の範囲
- タグは［やる気 1〜3］。タップで外せる。緩和は範囲の上限だけを上げる
- 結果画面の［もっと楽なのも見る］［もっと凝ったのも見る］：手間の範囲だけを下限・上限ともに1つずらす（1つだけ選んだときはそのレベルちょうどを基準）。
  他の条件（食材・味・否定・包丁なし・除外）はそのまま。1を下回ると外食・お惣菜の案内、4を超えるなら無効。
  ずらした先では緩和せず「このレベルの料理は◯品でした」。切り替え中は上部に現在の表示と［元の設定に戻す］
- やる気度を選んでいないときは、元の第1候補の手間を基準にずらす
- フリー入力：「凝ったのも見たい」→3〜4、「楽なのも見たい」→1〜2、「どっちでもいい」→絞り込みなし（質問済み）

## 「これにする」後の説明画面と調理器具（E）
- 結果の各候補の［これにする］で説明画面。［結果に戻る］で切り替え中の状態ごと戻る。今回は履歴に記録しない
- 表示：料理名・やる気バッジ、主役／脇役の食材、手間と調理法（茹でる→炒める）、必須／あれば便利な器具、調理時間・洗い物。
  手順の文章は出さない。「調味料・分量は検索で確認を」
- 家にあるもの（任意）：料理データで使う食材から複数選択。localStorage（nani-taberu:pantry）に保存し次回の初期値。足りない食材を強調、なければ「家にあるもので作れそうです」
- 調べる：レシピ・画像・材料・分量（料理名＋材料 分量。レシピの開く先）・買い足しのお店（スーパー。足りない食材があるときだけ）
- dishes.json に kind・toolsRequired・toolsOptional・cookMinutes・washing を追加（元の tools はなかったので新規に付与）
- 設定：持っている調理器具（profile.tools。localStorage nani-taberu:profile）と「器具で絞り込む」（初期オン）
- 登録済みかつオンのとき、必須器具が足りない料理は除外（緩和しない。「持っている器具で作れる料理は◯品でした」＋検索・設定見直し）。
  あれば便利が足りない料理は 0.5 減点し理由に「◯◯があるともっと楽です」。外食・お惣菜として出す料理には適用しない
- 「鍋かフライパンのどちらかでよい」のような「どれか1つ」は表せないため、代表の器具を必須にしている

## 量・脂質・カロリーと精度改善ケース（F）
- weight（軽い／普通／重い）を廃止し amount（少／普／多）に置き換え。重さの質問は「どのくらい食べたい？（軽め／ふつう／しっかり）」。全8問のまま
- 全63品に amount・fat（低／中／高）・calorie（低め／ふつう／高め）。数値は持たない。旧「重い」の多くは脂質の話だったので fat に寄せた
- 今日の方針（スタート画面のチェック、またはフリー入力）：脂質控えめ・カロリー控えめ・量はしっかり。タグとして表示し外せる
  - 脂質控えめ：脂質「高」を除外。3品未満、または指定した食材・料理がすべて消えるときは減点だけに緩めて表示
  - カロリー控えめ：低め＋／高め−（除外しない）。量はしっかり：多＋／少−
  - 重み：脂質 ＞ カロリー（設定で「カロリー優先」「同じ重み」）
  - 脂質控えめ＋量はしっかり：両方に合う料理（現状しゃぶしゃぶ・寄せ鍋の2品）を上位。3品未満なら件数を表示し［検索で探す］
- 方針は並び順に効く（質問で絞った候補の中で上位に来る）。除外は脂質「高」だけ
- 結果に［脂質低め］［カロリー控えめ］などのバッジと理由。「ヘルシー」とは断定しない。目安の注記を表示
- 説明画面に［カロリーを調べる］（料理名＋カロリー、Google検索）。検索語の方針語：脂質控えめ→ヘルシー、カロリー控えめ→低カロリー
- フリー入力：ガッツリ・お腹いっぱい→量 多、軽め・少なめ→量 少、あっさり・脂質控えめ・油少なめ→脂質控えめ、低カロリー→カロリー控えめ、ヘルシー→両方
- 精度改善ケース集：tests/accuracy-cases.json（src/logic/accuracy.test.ts で全件確認）。ずれは「入力→期待」で追加する
- ひらがな2文字以下：なす・ねぎ・えびだけは、後ろが文末・助詞・ひらがな以外なら文中でも拾う（「辛いなす」）。いか・たこ・タイは例外にしない

## スイーツ（G）
- sweets.json（18品。和5・洋4・焼き菓子2・果物1・冷菓3・乳製品1・いも2）。family・sweetness・refresh・fat・calorie・amount・temp・buy・ingredients（main のみ）・aliases。手間・包丁・調理法は持たない
- 食材辞書に あんこ・チョコ（甘味）、いちご・バナナ・りんご・みかん（果物）を追加。さつまいもは焼き芋・干し芋で使うようになった。categories.json に「果物」
- 入り方：スタート画面［甘いものを探す］、フリー入力の「甘いもの」「おやつ」「デザート」「スイーツ」（甘さ控えめ・和菓子・洋菓子などもスイーツの合図）。
  スイーツでしか使わない食材（チョコ・あんこ・果物・さつまいも）は「『チョコ』は甘いものでした。甘いものとして探しますか？［はい］［ごはんで探す］」
- 質問は最大5問：系統（7種類を5つにまとめる：和菓子／洋菓子・焼き菓子／果物・ゼリー・アイス／ヨーグルト／おいも）、甘さ、味わい、量、温度。
  分割の良い順。フリー入力の属性語はスイーツの質問に当てはめる（さっぱり→味わい、こってり→濃厚、和→和菓子など）
- 結果は3品（同じ系統は2品まで）。買える場所・甘さ・脂質・カロリーのバッジ、［近くのお店で探す］［画像を見る］［カロリーを調べる］。［レシピを探す］は出さない。目安の注記
- 食べ合わせ：説明画面の［食後の甘いものも探す］。こってり・脂質高・量多のあと→さっぱり＋、果物・冷菓・乳製品＋、脂質高−。辛いあと→乳製品・冷菓＋。軽いあと→量しっかり＋。理由を表示。［食べ合わせを使わない］
- 方針の引き継ぎ：ごはんで選んだ脂質控えめ・カロリー控えめを弱い補正で持ち越し（除外しない）。「食事の方針（脂質控えめ）を引き継いでいます」［引き継がない］。設定で「ごはんで選んだとおり（脂質＋カロリー）／脂質のみ」
- スタート画面の方針をつけて［甘いものを探す］を押したときも、脂質・カロリーは弱い補正として効く（量しっかりは使わない）
